🗄️ Build a Vector Database

Create a ChromaDB collection with documents from a domain of your choice, run semantic search queries, and analyse the results. No API key needed — we use a free local embedding model.

🐍 Python
📦 chromadb
🔢 sentence-transformers
🔑 No API key needed
📋 Requirements
📚

At least 15 documents

Movies, books, recipes, products, news articles — any domain you find interesting.

🏷️

Metadata on every document

At least one metadata field (e.g. category, year, author, genre).

🔍

5 different semantic queries

Queries that would NOT work with a simple keyword search — use concepts, not exact words.

📊

Show distances in the output

Print the similarity distance for each result. Discuss: which query gave the best results?

💻 Setup
1

Install dependencies

Run this once in your terminal or at the top of your notebook:

# No API key needed — all local pip install chromadb sentence-transformers
📝 Code Scaffold
2

Create collection and add documents

Use the free all-MiniLM-L6-v2 model — small, fast, no API key.

import chromadb from chromadb.utils.embedding_functions import SentenceTransformerEmbeddingFunction # Free local embedding model — no API key needed ef = SentenceTransformerEmbeddingFunction(model_name="all-MiniLM-L6-v2") client = chromadb.Client() collection = client.create_collection( name="my_collection", embedding_function=ef ) # --- Add your documents here --- collection.add( documents=[ "The Shawshank Redemption — a story of hope and friendship in prison", "Inception — a heist thriller set inside layers of dreams", "The Lion King — an animated film about a young lion reclaiming his kingdom", # ... add at least 15 total ], metadatas=[ {"genre": "drama", "year": 1994}, {"genre": "sci-fi", "year": 2010}, {"genre": "animation", "year": 1994}, # ... one metadata dict per document ], ids=["doc1", "doc2", "doc3"] # must be unique strings ) print(f"Collection created with {collection.count()} documents")
3

Run semantic queries

Ask questions using concepts — not the exact words in the documents:

# Example: query uses different words than the stored documents queries = [ "a movie about escaping a difficult situation", "film involving the subconscious mind", "story about growing up and taking responsibility", # ... add 5 queries total ] for query in queries: results = collection.query( query_texts=[query], n_results=3, include=["documents", "metadatas", "distances"] ) print(f"\n🔍 Query: '{query}'") print("-" * 60) for doc, meta, dist in zip( results["documents"][0], results["metadatas"][0], results["distances"][0] ): print(f" Distance: {dist:.4f} | {doc[:80]}...") print(f" Metadata: {meta}")
4

Write a short analysis (5–8 sentences)

In a comment block or a print statement at the end of your file, answer:

• Which query returned the most relevant results, and why?
• Did any query return a surprisingly good match — a document that matched the concept even though it didn't share any words?
• What distance threshold would you use to decide "this result is relevant"?

💡 A lower distance = more similar. ChromaDB uses L2 distance by default — 0.0 is a perfect match.
