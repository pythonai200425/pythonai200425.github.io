🌍 Chapter 01

Hello World Docker

Run your very first container and understand exactly what happens under the hood — from Docker Hub to your terminal screen.

🎯
Chapter Goal
Verify Docker is installed, run the classic hello-world container, and build a mental model of images, containers, and registries.

How Docker Works — Big Picture

Before running a single command, let's understand the three moving parts you'll work with every day:

🖼️

Image

A read-only template — like a recipe. It contains the OS, runtime, and your code, frozen in layers.

📦

Container

A running instance of an image. Isolated process with its own filesystem — start, stop, and delete freely.

☁️

Registry

A remote store for images. Docker Hub is the default — pull public images or push your own.

⚙️

Docker Daemon

The background service that actually builds, runs, and manages containers on your machine.

1 Check Docker is Running

Open a terminal and confirm Docker is installed and the engine is active:

bash
docker --version
docker info
ℹ️
What to expect
docker --version prints the version number. docker info prints engine stats — if it shows "Server: Docker Engine" you're good to go. If it errors, start Docker Desktop first.

2 Run Your First Container

bash
docker run hello-world

Watch what happens step-by-step:

  1. Docker checks your local cache — is the hello-world image already downloaded?
  2. If not, it pulls from Docker Hub: "Unable to find image locally… Pulling from library/hello-world"
  3. Docker creates a new container from the image
  4. The container runs, prints its greeting message, then exits
💡
Run it twice
Run the command a second time. Notice it's instant — the image is cached locally. No network call needed.

🎉 Bonus — A Really Cool One

Now that you've seen a plain text greeting, try this animated ASCII aquarium that runs entirely inside a container:

bash
docker run -it --rm danielkraic/asciiquarium

You'll get a live, colorful aquarium right in your terminal. Press q or Ctrl+C to quit.

💡
Two new flags explained
-it keeps the terminal interactive so you can see the animation. --rm automatically deletes the container the moment you exit — no cleanup needed.

3 Inspect Containers

bash
docker ps       # running containers only
docker ps -a    # ALL containers (including stopped)

You'll see hello-world listed in docker ps -a with status Exited. Exited containers are not deleted automatically — they linger until you remove them.

ColumnMeaning
CONTAINER IDUnique 12-char hex ID — you can use the first 3-4 chars in most commands
IMAGEWhich image this container was created from
STATUSUp (running) or Exited with an exit code
NAMESDocker auto-assigns a fun random name unless you use --name

4 Remove the Container

Stopped containers still occupy disk space. Clean them up:

bash
# Remove by container ID (use your own ID from docker ps -a)
docker rm <container_id>

# Or remove ALL stopped containers at once
docker container prune
⚠️
rm vs rmi
docker rm removes a container. docker rmi removes an image. Common confusion — containers are instances, images are templates.

Quick Exercise

  1. Run hello-world for the first time and note the download message.
  2. Run it a second time — observe that there's no pull this time.
  3. Use docker ps -a to find both stopped containers.
  4. Run docker images and locate the hello-world image and its size.
  5. Remove both containers with docker rm.
