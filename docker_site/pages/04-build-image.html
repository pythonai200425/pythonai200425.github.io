🏗️ Chapter 04

Build Your Own Image

Stop using other people's images — write a Dockerfile to package your own application and run it anywhere Docker is installed.

🎯
Chapter Goal
Write a Dockerfile, build a custom Python web server image, run it as a container, and understand how layer caching speeds up subsequent builds.

What Is a Dockerfile?

A Dockerfile is a plain text recipe. Each instruction adds a layer on top of the previous one — Docker caches each layer independently. If only your code changes, Docker reuses all the earlier layers and only rebuilds from that point forward.

  Layer 4  │ COPY app.py       ← your code (changes often)
  ─────────┤
  Layer 3  │ EXPOSE 8000       ← port declaration
  ─────────┤
  Layer 2  │ WORKDIR /app      ← set working directory
  ─────────┤
  Layer 1  │ FROM python:slim  ← base OS + Python (cached, rarely changes)

1 Create the Project Files

Create a folder called demo-app and add two files inside it:

demo-app/app.py

python
from http.server import BaseHTTPRequestHandler, HTTPServer


class Handler(BaseHTTPRequestHandler):
    def do_GET(self):
        self.send_response(200)
        self.send_header("Content-type", "text/plain")
        self.end_headers()
        self.wfile.write(b"Hello from custom Docker image!\n")

    def log_message(self, format, *args):
        print(f"[{self.address_string()}] {format % args}")


server = HTTPServer(("0.0.0.0", 8000), Handler)
print("Server running on port 8000")
server.serve_forever()

demo-app/Dockerfile

dockerfile
FROM python:3.12-slim
WORKDIR /app
COPY app.py /app/app.py
EXPOSE 8000
CMD ["python", "app.py"]
InstructionWhat It Does
FROMSet the base image — always the first instruction
WORKDIRSet the working directory for subsequent instructions
COPYCopy files from build context (your machine) into the image
EXPOSEDocument which port the app listens on (does not publish it)
CMDDefault command when the container starts — can be overridden

2 Build the Image

bash
docker build -t my-python-web:v1 demo-app

Breaking down the flags:

  • -t my-python-web:v1 — tag the image as name:version
  • demo-app — the build context: the folder Docker sends to the daemon (avoid huge folders!)

Watch the output — each step is a layer. On a second build, unchanged layers print "CACHED" — much faster.

💡
Layer caching rule of thumb
Put instructions that change rarely near the top (base image, install dependencies), and instructions that change often near the bottom (COPY your code). This maximises cache hits.

3 Run the Container

bash
docker run -d --name web1 -p 8000:8000 my-python-web:v1

Open http://localhost:8000 and you should see: Hello from custom Docker image!

4 Inspect the Image

bash
docker images                    # list all images
docker history my-python-web:v1  # see the layers
docker logs web1                 # see app output
docker exec -it web1 sh          # shell into the running container

Cleanup

bash
docker rm -f web1
docker rmi my-python-web:v1
🧪

Quick Exercise

  1. Change the response text in app.py to something custom (your name, a joke, etc.).
  2. Rebuild the image as my-python-web:v2 — notice that only the last COPY layer is rebuilt.
  3. Run v2 on port 8001 alongside v1 on port 8000.
  4. Compare both in the browser — two different versions of your app running simultaneously.
  5. Add a RUN pip install requests instruction to the Dockerfile and observe where the cache breaks.
