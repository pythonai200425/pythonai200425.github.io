🎼 Chapter 08

Docker Compose Basics

Replace long docker run commands with a clean declarative YAML file. Start, stop, and manage multi-service applications with a single command.

🎯
Chapter Goal
Write a docker-compose.yml defining Nginx + Redis services, start the whole stack with docker compose up -d, and learn the essential Compose commands.

Why Docker Compose?

Imagine running a web app that needs Nginx, Redis, and a database. Without Compose:

bash (without compose — painful)
docker network create myapp-net
docker run -d --name redis --network myapp-net redis
docker run -d --name web --network myapp-net -p 8083:80 nginx
# Now imagine doing this for 5 services, with volumes, env vars...
# And tearing it down: docker rm -f web redis && docker network rm myapp-net

With Compose, all of that is one YAML file and two commands.

1 Your First Compose File

Create a folder compose-demo and save this as docker-compose.yml:

yaml
services:
  web:
    image: nginx:latest
    ports:
      - "8083:80"

  redis:
    image: redis:latest
  docker-compose.yml
  ┌──────────────────────────────────────────────┐
  │  services:                                    │
  │    web:            ──────────▶  Container     │
  │      image: nginx              (nginx)        │
  │      ports: 8083:80                           │
  │                                               │
  │    redis:          ──────────▶  Container     │
  │      image: redis              (redis)        │
  │                                               │
  │  ↕ Both on same auto-created network ↕        │
  └──────────────────────────────────────────────┘
ℹ️
Auto-created network
Compose automatically creates a network named <folder>_default and connects all services to it. The services can reach each other by their service name — so the web service can talk to redis by just using redis as the hostname.

2 Start the Stack

bash
cd compose-demo
docker compose up -d

Compose will pull any missing images, create the network, and start both containers. Open http://localhost:8083 for the Nginx welcome page.

3 Essential Compose Commands

bash
docker compose ps          # list containers in this project
docker compose logs        # combined logs from all services
docker compose logs -f web # follow logs for a specific service
docker compose stop        # stop all without removing
docker compose start       # start stopped services
docker compose restart     # restart all
docker compose down        # stop AND remove containers + network
docker compose down -v     # also remove volumes (data loss!)
docker compose exec web sh # shell into the 'web' service
CommandRemoves Containers?Removes Volumes?
compose stopNo (just pauses)No
compose downYesNo
compose down -vYesYes

Updating Your Stack

Changed a port or image tag? Just re-run up — Compose is smart enough to only recreate changed services:

bash
# Edit docker-compose.yml, then:
docker compose up -d

# If you changed the image or build context, pull first:
docker compose pull
docker compose up -d
🧪

Quick Exercise

  1. Start the two-service stack with docker compose up -d.
  2. Change the host port from 8083 to 8084 in the YAML file.
  3. Run docker compose up -d again — Compose should recreate only the web service.
  4. Add a third service: adminer (lightweight DB GUI) with image adminer:latest on port 8085:8080.
  5. Run docker compose ps to confirm all three services are up.
  6. Tear everything down with docker compose down.
