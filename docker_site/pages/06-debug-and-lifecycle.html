🔍 Chapter 06

Debug & Lifecycle

Containers misbehave — learn how to observe, diagnose, pause, restart, and safely clean up Docker resources without losing data.

🎯
Chapter Goal
Use logs, stats, and exec to diagnose a running container, master the full container lifecycle, and clean up unused resources safely.

Container Lifecycle

                  docker run / docker start
                         │
                         ▼
                  ┌─────────────┐
       ┌─────────▶│   Running   │◀──────────┐
       │          └──────┬──────┘           │
  docker start           │              docker unpause
       │           docker stop/             │
       │           docker pause             │
  ┌────┴────┐            │            ┌─────┴─────┐
  │ Stopped │            ├───────────▶│  Paused   │

  docker rm      ┌──────────────┐

   (gone)

1 Start a Test Container

bash
docker run -d --name dbg-nginx -p 8082:80 nginx

2 Observe the Container

bash
docker ps                     # confirm running
docker logs dbg-nginx         # see output (visit http://localhost:8082 first for some entries)
docker logs -f dbg-nginx      # follow live (Ctrl+C to exit)
docker logs --tail 20 dbg-nginx  # last 20 lines only
docker stats dbg-nginx        # live CPU, memory, network I/O (q to quit)
docker inspect dbg-nginx      # full JSON metadata
💡
First debug step
When a container exits unexpectedly, always run docker logs <name> first. The crash reason is almost always in the logs. Then check the exit code with docker inspect <name> --format '{{.State.ExitCode}}'.

3 Shell into a Running Container

bash
docker exec -it dbg-nginx sh

Inside:

bash (inside container)
ls /usr/share/nginx/html   # the static files Nginx serves
cat /etc/nginx/nginx.conf  # nginx config
ps aux                     # running processes
exit
ℹ️
exec vs run
docker exec runs a command inside an already running container. docker run starts a brand new container from an image. Use exec for debugging, not for production workflows.

4 Lifecycle Commands

bash
docker pause dbg-nginx      # freeze all processes (SIGSTOP)
docker unpause dbg-nginx    # resume (SIGCONT)
docker restart dbg-nginx    # stop + start
docker stop dbg-nginx       # graceful shutdown (SIGTERM, then SIGKILL after 10s)
docker kill dbg-nginx       # immediate SIGKILL
docker start dbg-nginx      # restart a stopped container

5 Cleaning Up Docker Resources

Docker accumulates stopped containers, dangling images, and unused volumes over time. Use these targeted cleanup commands:

bash
docker container prune   # remove all stopped containers
docker image prune       # remove dangling (untagged) images
docker volume prune      # remove unused volumes (careful — data loss!)
docker network prune     # remove unused networks
docker system df         # see disk usage breakdown
⚠️
Nuclear option
docker system prune -a removes ALL stopped containers, ALL unused images, ALL build cache, and ALL unused networks. It frees a lot of space but you'll need to re-pull images. Never run this with --volumes unless you're sure.

Quick Exercise

  1. Start dbg-nginx, then visit localhost:8082 in a browser.
  2. Watch docker logs -f dbg-nginx — see the access log entry appear in real time.
  3. Pause the container. Try refreshing the browser — what happens?
  4. Unpause and confirm the browser works again.
  5. Stop the container, then use docker ps -a to confirm it's Exited. Start it with docker start and verify it's back.
  6. Run docker system df and identify which resource type is using the most space.
