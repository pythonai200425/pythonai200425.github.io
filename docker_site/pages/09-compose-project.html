🚀 Chapter 09

Compose Project: Python + PostgreSQL

Build a complete app stack: a Python service that writes to PostgreSQL — both managed by a single Compose file, with persistent data and automatic startup order.

🎯
Chapter Goal
Create a project with its own Dockerfile for the Python app, wire it to PostgreSQL using Compose, persist the DB data in a volume, and handle startup ordering with retry logic.

Project Architecture

  compose-python-postgres/
  ├── app.py              ← Python app (inserts + queries)
  ├── requirements.txt    ← psycopg dependency
  ├── Dockerfile          ← builds the app image
  └── docker-compose.yml  ← wires app + db together

  Services:
  ┌──────────────┐    DB_HOST=db    ┌──────────────────┐
  │     app      │─────────────────▶│       db         │
  │  (Python)    │                  │  (postgres:16)   │
  │  (builds     │                  │  volume: pg_data │
  │  from .)     │                  └──────────────────┘
  └──────────────┘
         │
    depends_on: db
    (starts after db container is created)

1 Create the Project Files

app.py

python
import os
import time
import psycopg

DB_HOST = os.getenv("DB_HOST", "db")
DB_NAME = os.getenv("DB_NAME", "appdb")
DB_USER = os.getenv("DB_USER", "appuser")
DB_PASS = os.getenv("DB_PASS", "apppass")

# Retry loop — PostgreSQL may not be ready immediately
for attempt in range(20):
    try:
        conn = psycopg.connect(
            f"host={DB_HOST} dbname={DB_NAME} user={DB_USER} password={DB_PASS}"
        )
        print(f"Connected on attempt {attempt + 1}")
        break
    except Exception as e:
        print(f"Waiting for DB... ({e})")
        time.sleep(1)
else:
    raise RuntimeError("Could not connect to database after 20 attempts")

with conn.cursor() as cur:
    cur.execute("""
        CREATE TABLE IF NOT EXISTS notes (
            id   SERIAL PRIMARY KEY,
            text TEXT NOT NULL
        )
    """)
    cur.execute("INSERT INTO notes (text) VALUES (%s)", ("Hello from compose app",))
    cur.execute("SELECT id, text FROM notes ORDER BY id")
    rows = cur.fetchall()

conn.commit()
conn.close()

print(f"\nAll {len(rows)} note(s) in database:")
for row in rows:
    print(f"  [{row[0]}] {row[1]}")
💡
Why the retry loop?
depends_on: db only waits for the container to start, not for PostgreSQL to be ready to accept connections. PostgreSQL takes a few seconds to initialise. The retry loop solves this gracefully.

requirements.txt

text
psycopg[binary]==3.2.1

Dockerfile

dockerfile
FROM python:3.12-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY app.py .
CMD ["python", "app.py"]
💡
Layer ordering for faster rebuilds
requirements.txt is copied and installed before app.py. This way, when you only change Python code, Docker reuses the pip install layer from cache.

2 The Compose File

yaml
services:
  db:
    image: postgres:16
    environment:
      POSTGRES_USER: appuser
      POSTGRES_PASSWORD: apppass
      POSTGRES_DB: appdb
    volumes:
      - pg_data:/var/lib/postgresql/data

  app:
    build: .
    depends_on:
      - db
    environment:
      DB_HOST: db
      DB_NAME: appdb
      DB_USER: appuser
      DB_PASS: apppass

volumes:
  pg_data:
KeyWhat It Does
build: .Build the image from the Dockerfile in current directory
depends_onStart db container before app
environmentInject env vars — notice DB_HOST is db (service name = DNS name)
volumes: pg_data:Top-level declaration required for named volumes

3 Run the Stack

bash
docker compose up --build

Expected output (after PostgreSQL starts):

output
app-1  | Waiting for DB... (connection refused)
app-1  | Connected on attempt 3
app-1  |
app-1  | All 1 note(s) in database:
app-1  |   [1] Hello from compose app
app-1 exited with code 0

Run docker compose up --build again — you'll see 2 notes because the PostgreSQL data persists in the pg_data volume!

Stop & Cleanup

bash
docker compose down        # stop & remove containers, keep the volume
docker compose down -v     # also delete the pg_data volume (reset DB)
🧪

Quick Exercise

  1. Run the stack twice with docker compose up --build — confirm the note count grows.
  2. Run docker compose down -v and then up again — confirm the count resets to 1.
  3. Add a simple Flask web API to app.py that returns the notes as JSON on GET /notes.
  4. Add ports: ["5000:5000"] to the app service and confirm you can hit the API from your browser.
  5. Add a third service — adminer — for a web UI to inspect the database.
