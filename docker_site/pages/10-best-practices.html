10 Best Practices

🪶

1. Use Slim Images

Prefer python:3.12-slim over python:3.12. Smaller = faster pulls, smaller attack surface.

📌

2. Pin Versions

Use nginx:1.25 not nginx:latest in production. latest changes silently and breaks things.

🙈

3. Use .dockerignore

Exclude .git, node_modules, *.pyc, and .env to keep build context small and fast.

🔒

4. No Hardcoded Secrets

Never put passwords in a Dockerfile. Use -e, --env-file, or Docker secrets.

🔄

5. One Process per Container

Don't run nginx + postgres + your app in one container. Split them — it makes scaling and debugging far easier.

💾

6. Use Volumes for Data

Never store database files or uploads inside the container filesystem — use named volumes so data survives restarts.

❤️

7. Add Health Checks

Let Docker know when your service is actually ready — not just when the process started.

🏗️

8. Multi-Stage Builds

Use separate build and runtime stages to strip compilers, test dependencies, and build tools from the final image.

🔍

9. Scan for Vulnerabilities

Run docker scout cves <image> or integrate trivy into your CI pipeline.

🔁

10. Keep Docker Updated

Update Docker Desktop regularly. New versions include security patches, BuildKit improvements, and Compose features.

Example: Multi-Stage Build

For compiled languages or when you need build tools that shouldn't be in the final image:

dockerfile
# Stage 1: Build
FROM python:3.12 AS builder
WORKDIR /app
COPY requirements.txt .
RUN pip install --user --no-cache-dir -r requirements.txt

# Stage 2: Runtime (smaller — no compiler, no pip cache)
FROM python:3.12-slim AS runtime
WORKDIR /app
COPY --from=builder /root/.local /root/.local
COPY app.py .
ENV PATH=/root/.local/bin:$PATH
CMD ["python", "app.py"]

The final image only contains the slim runtime and the installed packages — not the full Python build toolchain.

Example: Health Check

Tell Docker when your service is actually ready, not just started:

dockerfile
FROM nginx:1.25
HEALTHCHECK --interval=30s --timeout=5s --retries=3 \
  CMD curl -f http://localhost/ || exit 1

Or in a Compose file for PostgreSQL:

yaml
services:
  db:
    image: postgres:16
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U appuser -d appdb"]
      interval: 10s
      timeout: 5s
      retries: 5

  app:
    build: .
    depends_on:
      db:
        condition: service_healthy   # waits for HEALTH, not just started!
💡
The real solution to startup ordering
depends_on: condition: service_healthy combined with a health check is the correct fix for the "database not ready" problem — better than a retry loop in application code.

Complete Command Cheat Sheet

bash — containers
docker run -d --name web -p 8080:80 nginx   # start detached
docker run -it ubuntu bash                  # interactive shell
docker run --rm alpine echo hello           # auto-remove on exit
docker ps                                   # running containers
docker ps -a                                # all (including stopped)
docker logs -f web                          # follow logs
docker exec -it web sh                      # shell into container
docker stop web / docker start web          # graceful stop/start
docker rm -f web                            # force remove
bash — images
docker build -t myapp:v1 .                  # build image
docker images                               # list images
docker pull nginx:latest                    # pull from hub
docker rmi myapp:v1                         # remove image
docker history myapp:v1                     # show layers
bash — compose
docker compose up -d                        # start all services
docker compose up --build                   # rebuild then start
docker compose ps                           # list services
docker compose logs -f                      # follow all logs
docker compose exec web sh                  # shell into service
docker compose down                         # stop and remove
docker compose down -v                      # also remove volumes
bash — cleanup
docker system df                            # disk usage
docker container prune                      # remove stopped containers
docker image prune -a                       # remove unused images
docker volume prune                         # remove unused volumes
docker system prune -a                      # EVERYTHING unused

Final Challenge — Build Your Own Stack

Put everything together in one project:

  1. Create a Python Flask API with two endpoints: POST /items and GET /items.
  2. Add PostgreSQL as the database, connected with psycopg.
  3. Add Redis for caching the GET response.
  4. Wire all three with a single docker-compose.yml.
  5. Add a named volume for PostgreSQL data.
  6. Add a health check to the db service and use condition: service_healthy.
  7. Write a .dockerignore for the project.
  8. Document in a README: how to start, stop, and reset data.

You now have all the tools to build this. Go for it. 🚀
