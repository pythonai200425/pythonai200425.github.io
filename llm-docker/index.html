Configure the .env File
Copy the template and optionally choose a different model. This is where your settings live.
The .env file stores configuration values. Copy .env.example to .env using the terminal command below. The defaults work out of the box — you only need to edit if you want a different model.
Terminal
bash 
$ cp .env.example .env
Here is the full content of .env.example. Each line sets one variable that Python reads at startup.
.env.example
env 
# Where Python connects to reach the Ollama API
# Keep localhost:11434 — Docker maps that port for you
OLLAMA_BASE_URL=http://localhost:11434

# The model tag to load. Change this to try other models.
# Examples: llama3.2:3b (faster), mistral, gemma2:2b
OLLAMA_MODEL=llama3.1:8b
✅

Tip: Always add .env to your .gitignore file. The .env.example is safe to commit — it's just a template with no real secrets.

⚠️

Smaller model? Swap OLLAMA_MODEL=llama3.2:3b for faster replies on a slow machine. You'll also need to update the model name in docker-compose.yml (next step).

Step 3 of 6
docker-compose.yml
Two containers working together: one serves the model, one downloads it. Comments explain every line.
This file is the heart of the project. Docker Compose reads it and spins up two containers automatically. You never have to type a long docker run command.
docker-compose.yml
yaml 
# docker-compose.yml
# This file tells Docker Compose which containers to run and how to connect them.

services:

    # ── SERVICE 1: Ollama ──────────────────────────────────────────────────────
  # Ollama is an open-source LLM runner. It downloads models,
  # loads them into memory, and exposes a simple HTTP API for chat.
  ollama:
    image: ollama/ollama:latest   # official Ollama Docker image
    container_name: ollama         # gives the container a friendly name
    ports:
      - "11434:11434"               # host:container — exposes the API to your laptop
    volumes:
      - ollama_data:/root/.ollama   # persists downloaded models between restarts
    restart: unless-stopped         # auto-restart if it crashes (not on manual stop)

    # ── SERVICE 2: Model Puller ────────────────────────────────────────────────
  # A one-shot helper that waits for Ollama to be ready,
  # then downloads llama3.1:8b into the shared volume.
  # After first run it exits immediately (model already there).
  model-puller:
    image: ollama/ollama:latest   # reuses the same image — no extra download
    container_name: ollama-model-puller
    depends_on:
      - ollama                      # won't start until the ollama service is running
    environment:
      - OLLAMA_HOST=http://ollama:11434  # tells ollama CLI where the server is
                                               # "ollama" here is the service name above
    entrypoint: ["/bin/sh", "-lc"]  # run as a shell script
    command: |
      echo "Waiting for Ollama API...";
            # Loop until the API responds (Ollama needs ~2-3 seconds to boot)
      until ollama list > /dev/null 2>&1; do sleep 2; done;
      echo "Pulling model llama3.1:8b (~4.7 GB)...";
      ollama pull llama3.1:8b;      # skipped automatically if already downloaded
      echo "Model ready.";
    volumes:
      - ollama_data:/root/.ollama   # same volume → model lands where Ollama can find it
    restart: "no"                   # do NOT restart — it's a one-shot job

# Named volumes are managed by Docker.
# Data survives "docker compose down" but is removed by "docker compose down -v".
volumes:
  ollama_data:
🔍

How the two containers share the model: Both mount the same Docker volume (ollama_data). The puller downloads the model file there. Ollama reads it from there. No copying needed.

Run these three commands in order. The first installs the Python library. The second starts Docker Compose in the background. The third lets you watch the model download — wait for "Model ready." before moving on.
Terminal — run in order
bash 
# Step 1: Install the Python dependency into your active environment
$ pip install -r requirements.txt

# Step 2: Start both containers in the background (-d = detached mode)

Step 5 of 6
chat.py — The Code
Read through the full script. Every section is commented to explain what it does and why.
chat.py
python 
# ─────────────────────────────────────────────────────────────────────────────
# chat.py  —  Interactive CLI chat client for a local Ollama LLM
#
# HOW IT WORKS (big picture):
#   1. We wait until the Ollama HTTP API is reachable on localhost:11434
#   2. We enter a loop: read user input → send to API → print the reply
#   3. We keep all messages in a list so the model remembers the conversation
# ─────────────────────────────────────────────────────────────────────────────

# Standard library imports — no installation needed
import argparse    # reads command-line flags like --model, --max-tokens
import json        # converts Python dicts ↔ JSON strings for the HTTP API
import sys         # used to print errors to stderr instead of stdout
import threading   # runs the spinner animation in the background while waiting
import time        # used for the polling loop (sleep 1 second between retries)
from typing import List, Dict  # type hints — not required, but makes code readable

# The only external library (installed via requirements.txt)
import requests    # makes HTTP GET/POST requests — same library used for any web API

# ── DEFAULT VALUES ────────────────────────────────────────────────────────────
# These are used when the user does NOT pass command-line flags.
# They can all be overridden: python chat.py --model mistral --max-tokens 200
DEFAULT_BASE_URL   = "http://localhost:11434"  # Ollama's HTTP server address
DEFAULT_MODEL      = "llama3.1:8b"              # model name as registered in Ollama
DEFAULT_MAX_TOKENS = 120                        # max words in one reply (keep short on CPU)
DEFAULT_CONTEXT    = 1024                       # how many tokens the model can "see" back


# ── FUNCTION: wait_for_ollama ─────────────────────────────────────────────────
# Before we can chat, the Ollama server must be running AND the model loaded.
# This function polls /api/tags every second until it gets a 200 OK response.
# If Ollama isn't ready after `timeout_seconds`, we give up and return False.
def wait_for_ollama(base_url: str, timeout_seconds: int = 120) -> bool:
    for _ in range(timeout_seconds):
        try:
                        # GET /api/tags → Ollama returns a list of downloaded models
            r = requests.get(f"{base_url}/api/tags", timeout=2)
            if r.status_code == 200:
                return True     # server is up!
        except requests.RequestException:
            pass                # connection refused — server not up yet, try again
        time.sleep(1)           # wait 1 second before next attempt
    return False                # timed out


# ── FUNCTION: chat_once ───────────────────────────────────────────────────────
# Sends one turn of conversation to the Ollama API and returns the reply text.
#
# messages is a list of dicts, like:
#   [{"role": "system",    "content": "You are a helpful assistant."},
#    {"role": "user",      "content": "What is Docker?"},
#    {"role": "assistant", "content": "Docker is a containerisation tool..."},
#    {"role": "user",      "content": "Can you give an example?"}]  ← latest turn
#
# Sending the full history every time is how the model "remembers" context.
def chat_once(
    base_url: str,
    model: str,
    messages: List[Dict[str, str]],
    max_tokens: int,
    context_size: int,
) -> str:
        # Build the JSON body that Ollama's /api/chat endpoint expects
    payload = {
        "model":    model,       # which model to use
        "messages": messages,   # full conversation history
        "stream":   False,      # False = wait for full reply, True = stream tokens
        "options": {
            "num_predict": max_tokens,    # stop generating after this many tokens
            "num_ctx":     context_size,  # context window (smaller = faster, less memory)
        },
    }

        # POST /api/chat — sends the conversation, receives the reply
    r = requests.post(
        f"{base_url}/api/chat",
        headers={"Content-Type": "application/json"},
        data=json.dumps(payload),  # convert Python dict → JSON string
        timeout=600,               # 10 min timeout — CPU inference can be slow
    )

    if r.status_code != 200:
        raise RuntimeError(f"Ollama error {r.status_code}: {r.text}")

        # The response JSON looks like: {"message": {"role": "assistant", "content": "..."}}
    # We extract just the content string.
    return r.json()["message"]["content"]


# ── FUNCTION: show_wait_spinner ───────────────────────────────────────────────
# Prints a spinning animation while the model generates a response.
# Runs in a separate thread so the main thread can block on the HTTP request.
# stop_event.set() from the main thread signals it to stop.
def show_wait_spinner(stop_event: threading.Event) -> None:
    frames = ["|", "/", "-", "\\"]   # four frames make a rotation illusion
    i = 0
    while not stop_event.is_set():    # keep looping until main thread says stop
        print(f"\rAssistant is thinking {frames[i % 4]}", end="", flush=True)
                # \r moves cursor to start of line — overwrites previous frame
        i += 1
        time.sleep(0.2)                 # update 5 times per second
        # Clear the spinner line before the reply is printed
    print("\r" + " " * 40 + "\r", end="", flush=True)


# ── FUNCTION: interactive_chat ────────────────────────────────────────────────
# The main chat loop. Reads user input, calls chat_once(), prints the reply.
# Appends every message to `messages` so the model keeps track of context.
def interactive_chat(base_url, model, max_tokens, context_size) -> None:
    print(f"Connected to {base_url}  |  model: {model}")
    print("Type 'exit' to quit.\n")

        # The conversation history — starts with a system message that sets behaviour.
    # Every user + assistant turn gets appended here so the model sees the full chat.
    messages: List[Dict[str, str]] = [
        {"role": "system", "content": "You are a helpful assistant."}
    ]

    while True:
        user_input = input("You: ").strip()   # strip() removes leading/trailing whitespace

        if user_input.lower() in {"exit", "quit"}:
            print("Goodbye.")
            return

        if not user_input:
            continue   # skip empty input — go back to "You: " prompt

                # Add the user's message to the history before sending
        messages.append({"role": "user", "content": user_input})

        try:
                        # Start spinner in a background thread, then make the blocking HTTP call
            stop_event = threading.Event()
            t = threading.Thread(target=show_wait_spinner, args=(stop_event,), daemon=True)
            t.start()
            reply = chat_once(base_url, model, messages, max_tokens, context_size)
            stop_event.set()    # signal spinner to stop
            t.join(timeout=1)    # wait for spinner thread to finish cleaning up
        except Exception as exc:
            stop_event.set(); t.join(timeout=1)
            print(f"Error: {exc}", file=sys.stderr)   # print to stderr, not stdout
            messages.pop()     # remove the failed user message from history
            continue

        print(f"Assistant: {reply}\n")

                # Add assistant reply to history — model sees this in the next turn
        messages.append({"role": "assistant", "content": reply})


# ── FUNCTION: parse_args ──────────────────────────────────────────────────────
# Defines the command-line interface. argparse handles --flag parsing for us.
def parse_args() -> argparse.Namespace:
    parser = argparse.ArgumentParser(description="Chat with a local Ollama model")
    parser.add_argument("--base-url",      default=DEFAULT_BASE_URL)
    parser.add_argument("--model",         default=DEFAULT_MODEL)
    parser.add_argument("--max-tokens",    type=int, default=DEFAULT_MAX_TOKENS)
    parser.add_argument("--context-size",  type=int, default=DEFAULT_CONTEXT)
    return parser.parse_args()


# ── ENTRY POINT ───────────────────────────────────────────────────────────────
# Python runs this block when you execute: python chat.py
# It does NOT run when another file imports this module.
def main() -> None:
    args = parse_args()

        # Block here until Ollama responds (or timeout)
    if not wait_for_ollama(args.base_url):
        raise SystemExit("Ollama not reachable — run 'docker compose up -d' first.")

    interactive_chat(args.base_url, args.model, args.max_tokens, args.context_size)


if __name__ == "__main__":
    main()

Chat with Your Local LLM
Run chat.py and start a conversation. No internet needed from this point on.
Make sure docker compose up -d is running and you saw "Model ready." in the logs (Step 4). Then run one of these commands:
Terminal
bash 
# Default run — uses llama3.1:8b with 120 token limit
$ python chat.py

# Faster on slow machines — shorter replies, smaller context window
$ python chat.py --max-tokens 60 --context-size 512

# Use a different model (must already be pulled in Ollama)
$ python chat.py --model llama3.2:3b
What a typical session looks like:
Sample conversation
Connected to http://localhost:11434 | model: llama3.1:8b Type 'exit' to quit.   You: What is a Docker volume? Assistant is thinking /   Assistant: A Docker volume is a persistent storage mechanism managed by Docker that exists outside the container filesystem. Unlike bind mounts, volumes survive container removal and are managed with docker volume commands...   You: Give me a docker-compose example using one Assistant is thinking -   Assistant: Here's a simple example: services: web: image: nginx volumes: - mydata:/usr/share/nginx/html volumes: mydata:   You: exit Goodbye.
🧠

Why does the model remember what you said? Every turn, chat.py sends the entire conversation to Ollama — not just the latest message. The model reads from the start each time, which gives it "memory" of the session.

⚠️

First reply is slow — Llama 3.1 8B loads into RAM on the first inference. Replies after that are noticeably faster within the same session.

Keep this open while you work — the most useful docker and ollama commands.
docker & ollama commands
bash 
# ── Start / Stop ──────────────────────────────────────────────────────────────
$ docker compose up -d          # start all containers in background
$ docker compose down            # stop containers (models stay in volume)
$ docker compose down -v         # stop AND delete volume (re-downloads model!)

# ── Logs ──────────────────────────────────────────────────────────────────────
$ docker logs -f ollama          # follow Ollama server logs
$ docker logs ollama-model-puller # check if model downloaded

# ── Model Management ──────────────────────────────────────────────────────────
$ docker exec ollama ollama list  # list all downloaded models
$ docker exec ollama ollama pull mistral   # pull a different model
$ docker exec ollama ollama rm llama3.1:8b # delete a model to free disk

# ── Test the API directly ─────────────────────────────────────────────────────
$ curl http://localhost:11434/api/tags       # list models via HTTP
$ curl http://localhost:11434/api/version    # check Ollama version
docker compose up -d
Start everything. Use this every time you open a new coding session.

Stop containers cleanly. Models stay saved — next start is instant.
docker exec ollama ollama list
